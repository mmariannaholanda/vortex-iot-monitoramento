Laboratório Vortex · UNIFOR

Roteiro do desafio IoT

Do planejamento elétrico à entrega final — plano de 3 dias. Clique nos itens conforme for concluindo.

PROGRESSO GERAL 0 / 0
DIA 1 Eletrônica, firmware e primeiro endpoint ~9h
Planejamento elétrico 0h–2h
  • Abrir novo projeto no Wokwi com placa ESP32
  • Ligar módulo DHT22 — VCC/GND/OUT em pino digital (ex: GPIO 4)
  • Ligar módulo LDR — saída AO em pino ADC (ex: GPIO 34)
  • Ligar LED RGB — pinos R/G/B em GPIO 25, 26, 27, comum no GND
  • Ligar módulo botão — OUT em GPIO 18
  • Ligar módulo buzzer — I/O em GPIO 19
  • Salvar link público do projeto Wokwi (vai pro README depois)
Firmware — Wi-Fi + leitura simulada 2h–5h
  • Conectar ao Wi-Fi com WiFi.h
  • Definir ID único do dispositivo (ex: "esp-mari-01")
  • Função de leitura simulada (random()) para temperatura, umidade e luminosidade
  • Montar o JSON do payload igual ao exemplo do desafio
  • Implementar reconexão automática de Wi-Fi em caso de falha
Backend — primeiro endpoint 5h–8h
  • Instalar FastAPI + Uvicorn (pip install -r requirements.txt)
  • Criar tabela no SQLite (init_db())
  • Implementar POST /measurements
  • Testar com Postman/Insomnia ou /docs antes de plugar o ESP32
Conectar ESP32 → Backend 8h–9h
  • Rodar backend com --host 0.0.0.0
  • Ajustar firmware para fazer HTTP POST real (IP local da máquina)
  • Confirmar no terminal que os dados estão chegando e sendo salvos
DIA 2 API completa, dashboard e integração ~9h
Resto dos endpoints 0h–3h
  • Implementar GET /devices
  • Implementar GET /devices/{id}
  • Implementar GET /measurements (com filtro opcional por device)
  • Testar todos os endpoints manualmente em /docs
Dashboard mínimo 3h–6h
  • Página HTML/JS que busca dados via fetch() em GET /measurements
  • Mostrar temperatura, umidade, luminosidade
  • Mostrar status online/offline (comparar timestamp mais recente com "agora")
  • Atualização automática com setInterval
  • Deixar responsivo (funcionar em mobile)
Integração completa + atuadores 6h–9h
  • Rodar fluxo completo: ESP32 → API → banco → dashboard ao vivo
  • Lógica do LED RGB (ex: verde = normal, vermelho = temperatura alta)
  • Buzzer toca em condição de alerta
  • Botão silencia o alerta sonoro (variável alarmeSilenciado)
  • Caçar bugs de integração (é normal levar mais tempo que o previsto)
DIA 3 Documentação, vídeo e entrega ~8h
README e diário de IA 0h–3h
  • Instruções de como rodar backend, firmware e dashboard
  • Print do circuito no Wokwi com legenda dos pinos
  • Seção obrigatória de uso de IA: ferramentas, prompts, dificuldades, validação, reflexão
Vídeo de apresentação 3h–6h
  • 0:00–1:00 — Apresentação e visão geral
  • 1:00–3:00 — Demonstração prática do sistema
  • 3:00–5:00 — Explicação técnica do código
  • 5:00–6:00 — Uso da Inteligência Artificial
Revisão final e envio 6h–8h
  • Organizar pastas: Firmware/ Backend/ Frontend/ docs/ video/ README.md
  • Subir tudo pro GitHub/GitLab
  • Conferir todos os entregáveis da seção 11 do PDF
  • Enviar o link do repositório
